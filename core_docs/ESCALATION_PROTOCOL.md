# ESCALATION_PROTOCOL.md — 에스컬레이션 프로토콜

> Core Layer 문서. 에이전트가 자율 범위를 벗어났을 때 사람에게 결정을 요청하는 **행동 절차**.
> 에스컬레이션 **조건**은 `WORKFLOW.md` 섹션 6 참조.

---

## 1. 원칙

- 조건을 만나면 **즉시 멈춘다.**
- 추측으로 계속 진행하지 않는다.
- 부분 실행 금지 (파일 수정, 커밋 금지).
- 응답 대기 중 **관련 컨텍스트 보존**.

---

## 2. 보고 형식

```markdown
## 🚨 에스컬레이션

**상황**: (1~2줄)
**원인 조건**: (WORKFLOW 섹션 6 중 어느 조건)
**시도한 것**: (멈추기 전 무엇을 했는지)
**막힌 이유**: (왜 자율 결정 불가)

**선택지**:
- A) [옵션 A] — [장단점]
- B) [옵션 B] — [장단점]
- C) [옵션 C] — (있으면)

**추천**: (선택지 중 하나 + 이유, 없으면 "-")
**영향 범위**: (파일/기능)
```

---

## 3. 사람의 응답 패턴

| 응답 | 에이전트 행동 |
|------|------------|
| `A로 진행` (또는 B/C) | 즉시 재개 |
| `잠깐 멈춰` | 대기, 세션 종료 루틴 준비 |
| `방향 바꿔: [새 지시]` | `PLANS.md` 업데이트 후 새 지시로 재개 |
| `다른 선택지: [D]` | D로 재개 |
| `CONSTITUTION 개정 필요` | 개정 완료까지 대기 (실행 금지) |

---

## 4. 에스컬레이션 유형별 포함 정보

조건 유형에 따라 보고서에 반드시 포함해야 하는 정보.

| 조건 유형 | 필수 포함 정보 |
|----------|-------------|
| 선택지 충돌 | 2~3개 선택지 + 장단점 + 추천(근거 명시) |
| CONSTITUTION 충돌 | 모순되는 원칙 + 현실 상황. 개정 제안은 사람 판단 후에만 |
| 작업 범위 확대 | 현재 진행도, 남은 예상량, 선택지(분리/계속/롤백) |
| 외부 의존성 필요 | 의존성 목록 + 이유, 대안 검토 결과, 라이선스 |
| 반복 실패 (3회) | 시도별 에러 로그, 원인 가설, 수동 개입 지점 |
| Blocker 접촉 | open-decisions 항목 인용, 우회 가능 여부 |
| Small→Large 전환 | 무엇이 바뀌었는지, 현재까지 작업 내용 |

---

## 5. 응답 불가 시 (세션 한계 등)

사람 응답 없이 세션을 종료해야 하는 경우:

1. `NEXT_SESSION.md`에 **에스컬레이션 상태 명시**
2. 변경사항은 staged 유지 (가능하면 `git stash`)
3. 세션 종료 루틴 실행
4. 다음 세션에서 사람 응답 후 재개

### 핸드오프 메시지 추가 필드

일반 핸드오프 형식에 아래 추가:
```markdown
**상태**: ⚠️ 에스컬레이션 대기 중
**원인 조건**: [조건명]
**대기 중인 결정**: [선택지 A / B / C]
**작업 상태**: staged / stashed / 미변경
```

| 패턴 | 대응 |
|------|------|
