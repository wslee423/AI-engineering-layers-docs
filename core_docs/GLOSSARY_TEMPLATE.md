# GLOSSARY.md — 용어 정의

> 에이전트와 사람이 사용하는 용어의 명확한 정의.
> **용어 해석이 다르면 에이전트가 잘못된 시점에 다음 단계로 넘어간다.**

---

## 📋 작업 상태 용어

### "구현 완료" (Implementation Complete)
코드 작성 + 정적 분석 통과 + git staged 상태.
→ 다음: 검증 또는 자체 완료.

### "검증 통과" (Validation Pass)
`QUALITY_SCORE.md` 체크리스트(섹션 7) 모든 항목 OK.
→ 다음: 문서 동기화 + 커밋.

### "완료" (Done)
검증 통과 + 문서 업데이트 + 커밋 모두 끝.
→ 다음: 다음 기능 루프.

### "에이전트 실패" (Agent Failure)
정적 분석/테스트/규칙/구조/설정 중 하나에서 실패.
처리: 자체 수정 시도 → 같은 오류 3회 실패 시 에스컬레이션.

보고 형식은 `AGENTS_PATTERN.md` 섹션 4-2.

---

## 🎯 기능 분류 용어

### "작은 기능" (Small Feature)
`WORKFLOW.md` 섹션 3-1의 3가지 기준 **모두** 만족:
- 데이터 스키마 변경 없음
- 외부 API 신규 연동 없음
- CONSTITUTION 관련 없음

→ 에이전트 자체 완료 가능.

### "큰 기능" (Large Feature)
위 3가지 중 **하나라도** 해당 안 됨.
→ 검증 통과 후 사람 최종 승인 필요.

### "엣지 케이스" (Edge Case)
정상 흐름이 아닌 예외 상황 (네트워크 실패, 빈 입력, 권한 없음, 데이터 손상 등).
**UI뿐 아니라 API/백엔드 실패 처리도 포함**.

## 🤖 에이전트 표준 역할 (Core 정의)

**Core는 아래 6개 표준 역할을 정의한다.** 프로젝트는 이 중 필요한 것만 선택하고, 이름을 매핑한다.
새 역할 추가는 `AGENTS_PATTERN.md` 섹션 6 기준 통과 필요.

| 표준 역할 | 주요 책임 | 대표 이름 예시 |
|----------|----------|-------------|
| **Orchestrator** | 전체 기획, 작업 분석, 순서 결정 | Orchestrator |
| **Implementer** | 코드 구현 | Implementer / Implementor |
| **Reviewer** | 품질 검증, 규칙 준수 확인 | Reviewer / QA Agent |
| **Domain Agent** | 도메인 특화 산출물 생성 | Stage Builder, Data Pipeline, Prompt Builder 등 |
| **Doc Agent** | 문서 자동 동기화 | Doc Agent |
| **Progress Tracker** | 진행 상태 기록, 커밋 | Progress / Progress Tracker |

## 📊 용어 관계도

```
[사람] 방향 결정
    ↓
"구현" → "구현 완료"
    ↓
"검증" → "검증 통과" (or "에이전트 실패" → 재시도)
    ↓
(큰 기능이면) 사람 최종 승인
    ↓
"완료"
```

---

## 🚫 혼동 금지 사항

1. **"완료" ≠ "구현 완료"** — 완료는 문서+커밋까지 포함.
2. **"검증" ≠ "테스트"** — 검증은 QUALITY_SCORE 전체 확인. 테스트는 그중 한 항목.
3. **"작은 기능 자체 완료" ≠ "검증 생략"** — 검증은 반드시 수행. 생략되는 것은 사람 승인뿐.
4. **"에이전트 실패" ≠ "에스컬레이션"** — 실패는 자체 수정 시도. 에스컬레이션은 사람에게 넘김.
