# /sync-docs — 문서 동기화 + 커밋

Documenter 에이전트로서 코드 상태와 문서를 동기화하고 커밋한다.

---

## 실행 순서

### 1. 변경 범위 파악
```bash
git diff --name-only HEAD~1
```
최근 변경된 파일 확인. git 없으면 사람에게 어떤 기능이 완료됐는지 질문.

### 2. PLANS.md 업데이트
- 완료된 기능의 체크박스 처리: `[ ]` → `[x]`
- 완료일 기록

### 3. product-specs 동기화
구현 내용과 스펙 문서 비교:
- 구현된 내용이 스펙에 반영됐는가 → 미반영 시 업데이트
- 스펙과 구현이 다른 부분 → **임의 수정 금지, 사람에게 보고**

### 4. open-decisions 처리
결정된 항목 있으면:
- 상태 `결정됨` → `반영 완료`로 변경
- 반영 체크리스트 처리

### 5. tech-debt 업데이트
- 완료된 항목 상태 `완료`로 변경
- 새로 발견된 부채 항목 추가

### 6. git commit

```bash
git add .
git commit -m "[type]: [기능명]

- [구체적 변경 내용 1]
- [구체적 변경 내용 2]"
```

커밋 타입:
- `feat:` 새 기능
- `fix:` 버그 수정
- `docs:` 문서만 변경
- `refactor:` 리팩토링
- `test:` 테스트 추가/수정

### 7. NEXT_SESSION.md 갱신
`docs/exec-plans/NEXT_SESSION.md` 업데이트:
```markdown
## 🔖 다음 세션 핸드오프

**현재 Phase**: [Phase N]
**마지막 완료**: [기능명]
**다음 할 것**: [작업명 + 간략 설명]

**막힌 것**: (없으면 생략)
**결정 필요**: (없으면 생략)

**세션 종료 시각**: YYYY-MM-DD HH:MM
```

---

## 하지 않는 것

- 스펙과 구현이 다른 부분을 임의로 결정하지 않는다
- `core-beliefs.md` / `ARCHITECTURE.md`는 수정하지 않는다 (사람만)
- 미결 의사결정을 임의로 결정하지 않는다

---

## 보고 형식

```
## 문서 동기화 완료

업데이트된 문서:
- PLANS.md: [기능명] 체크 완료
- [기타 업데이트된 문서]

git commit: [hash] "[커밋 메시지]"

확인 필요한 항목: (있으면)
- [항목]: [이유]
```
