# /review — 코드 검증

Reviewer 에이전트로서 QUALITY_SCORE.md 기준으로 검증한다.
이슈 발견 시 직접 수정 후 재검증하는 루프로 실행.

---

## 실행 루프

```
체크리스트 전체 실행
  → 이슈 없음: "검증 통과" 보고
  → 이슈 있음: 직접 수정 후 재실행 (최대 3회)
  → 3회 후에도 실패: 에스컬레이션
```

직접 수정 범위: lint 에러, 타입 에러, 경미한 코드 수정
사람 승인 필요: 구조적 변경, 스키마 변경, 규칙 예외

---

## 체크리스트

### Step 1: 변경사항 확인
```bash
git diff
```
- [ ] 예상된 파일만 변경됨
- [ ] CONSTITUTION / CLAUDE.md / AGENTS.md 미변경

### Step 2: 정적 분석
```bash
[프로젝트 typecheck 명령어]
[프로젝트 lint 명령어]
```
- [ ] typecheck 경고 0건
- [ ] lint 경고 0건

### Step 3: 보안
- [ ] 모든 API 라우트 인증 확인 코드 존재
- [ ] PATCH/DELETE 라우트 소유권 확인 (user_id 검증)
- [ ] 시크릿/API 키 하드코딩 없음
- [ ] 클라이언트에 서버 전용 변수 노출 없음
- [ ] 신규 DB 테이블 RLS 활성화 (해당 시)

### Step 4: 안정성
- [ ] 외부 API 호출에 타임아웃 설정
- [ ] 에러 처리 존재 (빈 catch 블록 없음)
- [ ] API 실패 → 사용자에게 에러 전달

### Step 5: UI 상태 (UI 변경 있는 경우)
- [ ] Loading / Success / Error 3가지 모두 도달 가능
- [ ] Error가 Success 분기 안에 숨어있지 않음
- [ ] 상태 반응성 테스트 존재

변경사항: 예상 파일만 변경
정적 분석: ✅ typecheck / ✅ lint
보안: ✅ 인증 / ✅ 소유권 / ✅ 시크릿
안정성: ✅ 에러 처리 / ✅ 타임아웃
UI 상태: ✅ (또는 해당 없음)

- [파일명]: [수정 내용]

재작업 필요 (Implementer):
- [수정이 필요한 부분]
