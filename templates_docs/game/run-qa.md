# /run-qa — QA 검증 실행

QA Agent로서 QUALITY_SCORE.md 기준으로 테스트와 검증을 실행한다.
모든 단계를 순서대로 실행하고 결과를 요약 보고한다.

---

## 실행 순서

### 1. 정적 분석
```bash
[프로젝트 analyze 명령어]
```
경고 발생 시 즉시 수정 후 재실행.

### 2. 테스트 실행
```bash
[프로젝트 test 명령어]
```
실패 테스트는 원인 파악 후 수정 (Implementer 자율 수정 가능).

### 3. 핵심 파일 테스트 존재 확인
CLAUDE.md의 "핵심 파일 목록" 참조.
각 핵심 파일마다 테스트 1개 이상 존재하는지 확인.

### 4. 상태 반응성 테스트 확인 (UI 변경 있는 경우)
새로 추가된 HUD/오버레이가 있는 경우:
- `ValueNotifier` / `Signal` 변경 시 위젯 리빌드되는가
- 상태 반응성 테스트 존재 여부 확인

### 5. 스테이지 검증 (Stage Builder 작업 있는 경우)

스테이지 데이터 파일 전체 대상으로 확인:

| 항목 | 기준 |
|------|------|
| 스키마 유효성 | 필수 필드 존재 |
| 클리어 가능 여부 | 반드시 클리어 가능 |
| 수치 범위 | 구간별 기준 준수 |
| 드롭/배치 비율 | 기준 ±5% 이내 |

### 6. 발견된 문제 처리
- 즉시 수정 가능: 수정 후 해당 단계 재실행
- 즉시 수정 불가: `tech-debt-tracker.md`에 항목 추가

## 보고 형식

```
## QA 결과 요약

### 정적 분석
- 상태: ✅ 통과 / ❌ 실패
- 경고: N개

### 테스트
- 상태: ✅ 통과 / ❌ 실패
- 테스트 수: N개
- 실패 테스트: (있을 경우 목록)

### 핵심 파일 테스트
- 상태: ✅ 모두 존재 / ❌ 누락
- 누락: (있을 경우 파일명)

### 상태 반응성 테스트
- 상태: ✅ 존재 / ❌ 누락 / — 해당 없음

### 스테이지 검증
- 검증 파일: N개
- 상태: ✅ 전체 통과 / ❌ N개 실패
- 실패 항목: (있을 경우 파일명 + 사유)

### 신규 tech-debt
- (있을 경우 목록, 없으면 "없음")

### 종합 판정
- ✅ QA 통과 → Documenter로 인수인계
- ❌ QA 실패 → Implementer 재작업 필요: [내용]
```
