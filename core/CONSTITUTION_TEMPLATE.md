## 2. 문서 위계

충돌 시 상위 문서가 이긴다.

```
CONSTITUTION.md              ← 최상위
  ↓
[프로젝트 철학 문서]          ← 선택사항 (core-beliefs.md, PRODUCT_SENSE.md 등)
  ↓
CLAUDE.md                    ← 에이전트 운영 규칙
  ↓
AGENTS.md                    ← 역할 및 자율 범위
  ↓
QUALITY_SCORE.md             ← 품질 기준
  ↓
product-specs/*.md           ← 기능 스펙
  ↓
ARCHITECTURE.md              ← 기술 구현
```

**철학 문서 선택 가이드:**
- 게임, 콘텐츠 제품처럼 **설계 철학이 복잡한 경우** 두기 권장
- 단순 CRUD 툴은 **생략 가능** (CLAUDE.md가 바로 하위)

하위 문서가 상위 문서와 모순되면, 에이전트는 상위 문서를 따르고 사람에게 보고한다.

## 3. 에이전트 자율 범위

`AGENTS.md`의 **"자율 결정 가능한 것"**으로 명시된 범위 내에서만 사람 승인 없이 결정한다.
**명시되지 않은 것은 자율 범위가 아니다.**

## 4. 충돌 해결

### 4-1. 에이전트 간 충돌
QA 성격 에이전트는 `QUALITY_SCORE.md` 미달을 이유로 **거부권** 행사 가능.
그 외 충돌(구현 방식, 스펙 해석 등)은 사람이 최종 결정.

### 4-2. 에이전트 ↔ 문서 충돌
임의 결정 금지. 사람에게 보고 후 지시받는다.

### 4-3. 문서 간 충돌
섹션 2 위계 따름. 위계로 해결 안 되면 사람에게 보고.

## 5. 불변 원칙 (Immutable Principles)

어떤 상황에서도, 어떤 에이전트도 어길 수 없다.
사람도 바꾸려면 헌법 전체를 개정해야 한다.

**좋은 불변 원칙의 조건:**
- 검증 가능 (Pass/Fail 판정 가능)
- 예외 없음
- 왜 중요한지 명확

**개수 제한: 최대 5개.** 많을수록 힘이 약해진다.

2. **[원칙 제목]** — ...
3. **[원칙 제목]** — ...

## 6. 개정 절차

- 개정 **실행은 사람만** 가능
- 에이전트는 **개정 제안**만 가능 (이유와 함께)
- 에이전트는 헌법과 현실의 **모순 발견 시 반드시 보고**
- 개정 시 변경 이유를 하단 이력에 기록
