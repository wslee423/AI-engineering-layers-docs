# tech-debt.md — 기술 부채 추적

> 에이전트와 사람이 공통으로 관리하는 기술 부채.
> 버그, 리팩토링, 성능 개선 항목을 우선순위별로 관리한다.

---

## 1. 우선순위

| 레벨 | 기준 | 대응 |
|------|------|------|
| 🔴 Critical | 크래시, 데이터 손실, 보안 취약점 | 즉시 수정 |
| 🟠 High | 주요 기능 비정상 | 같은 세션 / 다음 Phase 내 |
| 🟡 Medium | 성능/UX 저하 | 현재 또는 다음 Phase |
| 🟢 Low | 코드 품질 개선 | 여유 있을 때 |

---

## 4. 자동 등록 트리거 (에이전트용)

아래 상황에서 에이전트는 자동으로 항목을 추가한다.

- 정적 분석 경고 (즉시 수정 불가)
- 테스트 실패 (즉시 수정 불가)
- 리팩토링 필요 (작업 범위 밖)
- 성능 기준 미달 (`QUALITY_SCORE.md`)
- 새로운 안티패턴 발견
- 외부 의존성 deprecation 경고

**최소 등록 정보**: ID, 우선순위, 한 줄 설명, 발견 시점, 관련 파일.
나머지는 사람 또는 다음 작업 시 보충.

## 6. 부채 적체 경고 (권장치)

**아래 수치는 권장치. 프로젝트 성격에 맞게 조정 가능.**

| 상황 | 의미 | 권장 조치 |
|------|------|----------|
| 🔴 Critical 1개 이상 | 즉시 대응 필요 | 현재 기능 루프 중단, 부채 먼저 |
| 🟠 High 3개 이상 | Phase 진행에 영향 | 다음 기능 시작 전 일부 해소 |
| 🟡 Medium 10개 이상 | 완성도 저하 | Phase 완료 시 일괄 처리 |
| 🟢 Low 20개 이상 | 코드베이스 건강도 저하 | 정기 리팩토링 세션 편성 |

에이전트는 Phase 완료 선언 시 위 상황 감지하여 사람에게 보고.

---

## 7. 부채로 분류하지 않는 것

아래는 tech-debt 대신 다른 문서로 관리:

- **미결 의사결정** → `open-decisions.md`
- **새 기능 요구** → `PLANS.md`의 다음 Phase
- **문서 누락/불일치** → Doc 에이전트가 즉시 처리
- **사람 승인 필요 변경** → 에스컬레이션
