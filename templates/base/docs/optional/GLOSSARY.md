# GLOSSARY.md — 용어 정의

> 에이전트와 사람이 사용하는 용어의 명확한 정의.
> **용어 해석이 다르면 에이전트가 잘못된 시점에 다음 단계로 넘어간다.**

---

## 📋 작업 상태 용어

### "구현 완료" (Implementation Complete)
코드 작성 + 정적 분석 통과 + git staged 상태.
→ 다음: 검증 또는 자체 완료.

### "검증 통과" (Validation Pass)
`QUALITY_SCORE.md` 체크리스트 전체 항목 OK.
→ 다음: 문서 동기화 + 커밋.

### "완료" (Done)
검증 통과 + 문서 업데이트 + 커밋 모두 끝.
→ 다음: 다음 기능 루프.

### "에이전트 실패" (Agent Failure)
정적 분석/테스트/규칙/구조/설정 중 하나에서 실패.
처리: 자체 수정 시도 → 같은 오류 3회 실패 시 에스컬레이션.

보고 형식은 `AGENTS_PATTERN.md` 섹션 4-2.

---

## 🎯 기능 분류 용어

### "작은 기능" (Small Feature)
`WORKFLOW.md` 섹션 3-1의 3가지 기준 **모두** 만족:
- 데이터 스키마 변경 없음
- 외부 API 신규 연동 없음
- CONSTITUTION 관련 없음

→ 에이전트 자체 완료 가능.

### "큰 기능" (Large Feature)
위 3가지 중 **하나라도** 해당 안 됨.
→ implementer subagent 사용. 검증 후 흐름은 `orchestrate.md` §3-B 참조.

### "엣지 케이스" (Edge Case)
정상 흐름이 아닌 예외 상황 (네트워크 실패, 빈 입력, 권한 없음, 데이터 손상 등).
**UI뿐 아니라 API/백엔드 실패 처리도 포함**.

## 🤖 에이전트 역할

현재 시스템의 4개 역할. 상세 구조는 `AGENTS_PATTERN.md` 참조.

| 역할 | 실행 주체 | 주요 책임 |
|------|---------|---------|
| **Orchestrator** | Main Claude Session (별도 파일 없음) | 기능 크기 판단, 작업 흐름 조율, Small Feature 직접 구현 |
| **Implementer** | subagent | 코드 구현 (Large Feature) |
| **Reviewer** | subagent (READ-ONLY) | 품질 검증, QUALITY_SCORE 체크리스트 판정 |
| **Documenter** | subagent | 문서 동기화(Mode A), 교훈 승격(Mode B) |

## 📊 용어 관계도

```
[사람] 방향 결정
    ↓
"구현" → "구현 완료"
    ↓
"검증" → "검증 통과" (or "에이전트 실패" → 재시도)
    ↓
(큰 기능이면) 사람 최종 승인
    ↓
"완료"
```

---

## 🚫 혼동 금지 사항

1. **"완료" ≠ "구현 완료"** — 완료는 문서+커밋까지 포함.
2. **"검증" ≠ "테스트"** — 검증은 QUALITY_SCORE 전체 확인. 테스트는 그중 한 항목.
3. **"작은 기능 자체 완료" ≠ "검증 생략"** — 검증은 반드시 수행. 생략되는 것은 사람 승인뿐.
4. **"에이전트 실패" ≠ "에스컬레이션"** — 실패는 자체 수정 시도. 에스컬레이션은 사람에게 넘김.
