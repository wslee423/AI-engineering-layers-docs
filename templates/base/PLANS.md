## Phase 구조

| Phase | 이름 | 목표 | 상태 |
|-------|------|------|------|
| Phase 1 | 기반 세팅 | 개발 환경 + 코어 구조 | 🔲 |
| Phase 2 | MVP | 핵심 기능 동작 | 🔲 |
| Phase 3 | 완성 | 출시 가능 상태 | 🔲 |
| Phase 4 | 출시 후 | 개선 및 확장 | 🔲 |

*(Phase는 프로젝트 규모에 맞게 추가/삭제)*

상태 아이콘: 🔲 미시작 / 🔄 진행 중 / ✅ 완료

---

## Phase 1 — 기반 세팅

**목표**: 개발 환경 구성 + 코어 아키텍처 완성. 이 Phase 없이는 다음 Phase 시작 불가.

### 완료 조건 (Phase Gate)
- [ ] 프로젝트 초기 세팅 완료 (패키지, 환경변수, 배포 파이프라인)
- [ ] 정적 분석 경고 0건
- [ ] 테스트 파이프라인 작동 확인
- [ ] `ARCHITECTURE.md` 초안 작성 완료

### 작업 목록
- [ ] 프로젝트 초기화
- [ ] 패키지/의존성 설치
- [ ] 환경변수 설정
- [ ] CI/CD 설정 (선택)
- [ ] 인증 기본 구조 (SaaS) / 게임 루프 기본 구조 (Game)
- [ ] DB 스키마 초안 (SaaS) / 저장소 구조 (Game)

---

## Phase 2 — MVP

**목표**: 핵심 기능이 end-to-end로 동작. 실제로 써볼 수 있는 상태.

### 완료 조건 (Phase Gate)
- [ ] 핵심 기능 [N]개 구현 완료
- [ ] 전체 테스트 통과
- [ ] 정적 분석 경고 0건
- [ ] 실제 환경에서 동작 확인 (배포 또는 디바이스)

### 작업 목록
- [ ] [핵심 기능 1]
- [ ] [핵심 기능 2]
- [ ] [핵심 기능 3]
- [ ] 에러 처리 + 엣지 케이스
- [ ] 기본 UI/UX

---

## Phase 3 — 완성

**목표**: 출시 가능한 완성도.

### 완료 조건 (Phase Gate)
- [ ] Phase 2 완료 조건 모두 통과
- [ ] `QUALITY_SCORE.md` 출시 전 체크리스트 통과
- [ ] 미결 의사결정(`open-decisions.md`) 🔴 Blocker 없음

### 작업 목록
- [ ] [추가 기능 1]
- [ ] [추가 기능 2]
- [ ] 성능 최적화
- [ ] 최종 QA

## Phase 4 — 출시 후 *(선택)*

**목표**: 피드백 반영 및 기능 확장.

### 작업 목록
- [ ] [피드백 기반 개선]
- [ ] [신규 기능]

## 원칙

1. 정상 동작 먼저 — 완벽한 코드보다 동작하는 코드 우선
2. 엣지 케이스는 나중에 — 정상 경로 완성 후 처리
3. Phase Gate 통과 후 다음 Phase 진입
